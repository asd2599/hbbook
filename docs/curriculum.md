> 말로 만드는 웹페이지(H Chat Pro) → 반복업무를 고정하는 방과 내 PC를 다루는 Agent(프로젝트 · 커넥터 · 데스크탑) →

    - `cd /d "%~dp0"` 로 bat 이 있는 폴더에서 돈다.
    - **Node.js 가 없으면** 설치 안내 후 `pause`.
    - `node server.js --open` 을 **그 창에서 그대로** 돌린다(백그라운드 금지).
      **포트는 bat 이 신경 쓰지 않는다** — server.js 가 비어 있는 포트를 잡고 그 주소를 직접 연다.
      **어느 갈래로 끝나든 `pause`** 라 창이 바로 닫히지 않는다.
    - 실제로 돌려 확인했다 — 노드 없음 · 정상 실행 · 배포판 더블클릭.

- **앱을 두 개 띄울 때 주소가 겹치던 문제를 잡았다** (강사 질문에서 확인).
  base 폴더로 실습한 다음 그 폴더를 복사해 자기 앱을 만들면, 서버가 두 개 뜬다.
  - **`tryListen` 버그** — 재시도할 때마다 `listen` 성공 콜백이 `on` 으로 **쌓여서**,
    실제로는 8789 에 떠 있는데 터미널에는 `READY http://localhost:8787` 부터 줄줄이 찍혔다.
    학생이 첫 줄을 보고 **남의 앱 주소**를 열게 되는 상황이었다.
    `once` 로 바꾸고 매번 걷어내며, 주소는 `server.address().port` 에서 가져오도록 고쳤다.
    이제 **실제로 열린 포트 한 줄만** 찍힌다.
  - **`--open` 옵션** — `node server.js --open` 이면 실제로 열린 주소를 브라우저로 띄운다.
    실행.bat 이 이 옵션을 쓰고, 실습 중에는 그냥 `node server.js` 로 띄운다.
  - **떠 있는 서버를 죽이고 여는 방식은 쓰지 않는다**(강사 질문에서 검토). 교안에는 두 개가 동시에
    떠 있는 게 정상인 순간이 있다 — **36p 에서 개발 중인 앱을 띄워 둔 채 배포판을 다른 폴더에 풀어
    시험**할 때다. 자동으로 죽이면 그때 개발 중인 서버가 꺼진다. 8787 을 다른 사내 프로그램이 쓰고
    있을 때 PID 만 보고 죽이는 위험도 있다. 대신 **혼란만 없앤다** —
    실행.bat 은 이미 떠 있으면 *그건 그대로 두고, 이 앱은 다른 주소로 엽니다* 라고 **알려만 주고**,
    server.js 는 **창 제목에 실제 주소**를 넣어(`AI App http://localhost:8788 - 닫으면 꺼집니다`)
    검은 창이 여러 개여도 어느 앱인지 보이게 한다. 제목은 **진짜 콘솔일 때만** 보낸다 —
    출력이 파이프로 넘어가면 깨진 글자가 찍히기 때문에 `process.stdout.isTTY` 로 막았다.
  - 확인: base 는 8788, 복사한 my-app 은 8789 에 뜨고 **각자 자기 폴더의 화면**을 연다.
    `app.html` 이 `location.origin` 을 쓰므로 API 도 각자 자기 서버로 간다. 키는 브라우저 메모리에만
    있고 포트가 다르면 오리진도 달라, 앱마다 키를 한 번씩 넣으면 된다.
