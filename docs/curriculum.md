## 2. 설계 방향 및 교안 작성 원칙

### 2.1 설계 방향

일반직 관점의 **업무 문제 → 학습 목적 → 쉬운 개념 설명 → 실습 → 결과 확인 → 현업 적용**으로 연결한다.
개발·기술 자체보다 **"내 업무에서 어떻게 활용할 수 있는가"** 를 먼저 이해하도록 구성한다.

### 2.2 교안 작성 7원칙

1. 일반직 관점의 업무 문제에서 출발해 현업 적용까지 하나의 흐름으로 연결한다.
2. 실습명만 제시하지 않고 **"왜 하는가 / 무엇을 해결하는가 / 무엇이 남는가"** 를 함께 명시한다.
3. 초반은 즉시 결과가 나오는 쉬운 실습으로 시작하고 점진적으로 난이도를 올린다.
4. 각 실습 종료 시 **현업 적용 예시**와 가능하면 **Before → After** 를 반드시 정리한다.
5. 사내 기밀 대신 **검증된 교육용 Mock Data** 를 사용한다.
6. 외부 Skill 다운로드·GitHub 의존 실습은 제외하고 **사전 제공 자료 중심**으로 구성한다.
7. 실습 실패 시 다음 단계로 진행 가능한 **완료본 / 대체 경로**를 준비한다.

## M1. H-Chat으로 시작하는 AI 업무 활용 `08:10~09:10 · 60분`

> **학습목표**: 대화형 AI의 기본 원리와 H-Chat 핵심 기능을 이해하고, 자연어만으로 웹페이지를 만들어 교육 플랫폼에 공유한다.
>
> **2026-09-05 변경** — M1-3(COSTAR)·M1-4(프로젝트)를 **웹페이지 제작 실습**으로 대체했습니다. 원본 CSV 설계와 다른 부분이며, 변경 근거는 담당자 요청입니다.

### M1-1. AI 활용의 변화 `08:10~08:20 · 10분` · 개념

- **세부 모듈**: AI 활용의 변화 (대화형 AI → 반복업무 구조화 → Agent 활용)
- **교안 반영 유의사항**
  - AI를 '질문하면 답하는 챗봇' 정도로만 이해하면 이후 Agent/자동화의 필요성이 와닿지 않음
  - "대화형 AI에서 Agent로 확장되며 업무 효율화가 가능해진다"는 흐름과 **사람 개입의 중요성** 설명

### M1-2. H-Chat 모델·기능 한눈에 이해 `08:20~08:30 · 10분` · 개념

- **세부 모듈**: H-Chat 모델·기능 한눈에 이해 (모델 / 프로젝트 / 커넥터)
- **교안 반영 유의사항**
  - H-Chat Pro에서 어떤 기능을 어떤 업무에 쓰는지 **선택 기준** 안내
  - 비유로 설명 — 모델 = '업무에 따라 선택하는 엔진', 프로젝트 = '반복업무 전용 작업공간', 커넥터 = '업무자료와 연결하는 통로'
  - **모델이란 무엇인가**를 초등학생 눈높이로 먼저 설명 — '내 말을 알아듣고 대신 글을 써주는 AI의 머리',
    말한다 → 모델이 생각한다 → 답이 나온다. 회사마다 잘하는 일이 달라 여러 개를 골라 쓴다는 것까지
  - 회사별 특성(OpenAI/Claude/Gemini)과 회사 안의 '똑똑한 쪽 / 빠른 쪽' 두 갈래 구조
  - H-Chat Pro의 외부 AI 툴 대비 특장점 소개 (3개 LLM 모델 무료 사용, API 무료 사용, Confluence/Jira 연결 등)
- **현업 적용**: 내 업무에 맞는 모델을 '기능이 아니라 **업무 성격(정확성·창의성·속도)**' 기준으로 선택

### M1-3. 말로 만드는 웹페이지 `08:30~08:45 · 15분` · 개념+실습+시연

- **교안 반영 유의사항**
  - 글 결과물만 보면 'AI가 대신 만들어 준다'는 감각이 잘 남지 않음 → **눈에 보이는 결과물**을 직접 만들게 함
  - 웹페이지 = '인터넷에서 보는 한 장의 화면', HTML = '그 화면을 어떻게 그릴지 적어둔 설계도 한 장'
  - 설계도는 AI가 쓰고 **교육생은 말로 부탁만 한다** — 코딩 지식·프로그램 설치 불필요
  - 순서는 네 단계: **말로 부탁 → 코드 받기 → [HTML 미리보기]로 확인 → 말로 고치기**
  - 파일 저장·더블클릭 없이 **H-Chat 화면 안에서 만들고 바로 확인**한다 (저장은 M1-4 업로드 때 1회)
  - 미리보기 슬라이드에서는 클릭 위치(①)와 결과 화면(②)만 짚는다
  - 교안의 프롬프트는 받아 적지 않도록 **[복사] 버튼**으로 제공한다
- **[실습] 첫 웹페이지 만들기**
  - **목적**: 코딩을 배우지 않고도 말 한 문장으로 결과물이 만들어진다는 것을 직접 확인
  - **실습 전 설명**: 지금까지 AI는 '글'을 써 줬다 → 이번에는 '화면'을 만든다
  - **절차**
    1. H-Chat 새 대화 열기 (모델은 '똑똑한 쪽')
    2. 제공된 문장을 그대로 붙여넣고 실행
       — "나를 소개하는 웹페이지를 HTML 파일 하나로 만들어줘. 제목은 'OOO의 소개 페이지', 인사말 한 줄,
       내가 좋아하는 것 3가지 목록을 넣어줘. 디자인도 같은 파일 안에 넣고, 코드 전체를 한 번에 보여줘."
    3. 결과 아래 **[HTML 미리보기]** 클릭 → 오른쪽 화면에서 결과 확인
  - **준비물**: H-Chat Pro 새 대화 1개 (이름 자리에 본인 이름) / 완료본 HTML 1종(실패 대비)
  - **현업 적용**: 업무 안내 페이지·행사 안내·설문 안내 화면을 같은 방식으로 제작
- **[시연] 말로 고치기 (Before → After)**
  - **목적**: 코드를 건드리지 않고 문장만으로 결과물을 고칠 수 있음을 보여줌
  - **절차**
    1. 처음 결과 화면 제시
    2. "인사하기 버튼을 누르면 폭죽이 터지게 해줘" 수정 문장 실행 (교안에서 [복사] 버튼으로 제공)
    3. 바뀐 화면을 나란히 비교
    4. 자주 쓰는 수정 문장 4종 정리 — 색·분위기 / 배치·크기 / 내용 추가 / 기기 대응
  - **강조**: 한 번에 다 고치지 말고 **한 번에 하나씩**

### M1-4. 나만의 웹페이지 만들고 플랫폼에 올리기 `08:45~09:00 · 15분` · 실습

- **교안 반영 유의사항**
  - 자유 창작 시간은 **10분**. 교안 슬라이드에는 시간을 적지 않고 강사가 구두로 안내한다
    (필요하면 강사가 `timer.html?m=10` 을 직접 열어 카운트한다 — 슬라이드에 버튼은 두지 않는다)
  - '잘 만드는 것'이 아니라 **'말로 만들어진다'는 감각**을 얻는 것이 목적임을 명시
  - 업무와 무관한 주제도 허용
- **[실습] 나만의 웹페이지 자유 창작**
  - **목적**: 처음부터 끝까지 자연어만으로 결과물 하나를 완성
  - **절차**
    1. 주제 정하기 (예시 제공 — 나를 소개하는 한 장 / 우리 팀 안내 / 오늘 배운 것 정리 / D-day·목록)
    2. H-Chat에 한 문장으로 부탁 (교육생이 직접 문장을 만든다)
    3. [HTML 미리보기]로 확인
    4. 마음에 들 때까지 말로 고치기
  - **준비물**: 주제 예시 4종 / 완료본 HTML 1종(막힌 교육생용)
- **[실습] 결과물 올리기 — 교육 플랫폼**
  - **목적**: 내 PC 안에만 있던 결과물을 누구나 열어볼 수 있는 형태로 공유
  - **절차**
    1. 완성 코드를 복사해 메모장에 붙여넣고 `이름.html` 로 저장 (파일 형식 '모든 파일', 인코딩 UTF-8)
    2. `hyundai.mincoding.co.kr` 강의장 접속
    3. 상단 **[질문있어요]** 메뉴 클릭
    4. 공지글 **'나만의 창작물을 올려주세요'** 열기
    5. 댓글 작성창의 **파일 업로드**로 `.html` 첨부 + 한 줄 소개 → [입력]
  - **준비물**: 게시판 공지글 사전 등록(관리자) / 파일 업로드 가능 여부 사전 점검
  - **실패 대비**: 확장자가 `.html` 인지 확인 → 그래도 안 되면 조교가 대신 업로드
  - **현업 적용**: 결과물을 링크·파일로 공유하는 흐름을 그대로 사내 업무에 적용

### M1-5. 서로의 결과물 보기 `09:00~09:10 · 10분` · 공유+피드백

- **목적**: '다른 사람은 어떤 문장으로 부탁했는지'를 보며 프롬프트 패턴을 자기 것으로 만들기

  2. 마음에 드는 것 1개를 고르고 '어디가 좋았는지' 한 줄 댓글

### M2-1. 프로젝트란 무엇인가 `09:20~09:30 · 10분` · 개념

- **교안 반영 유의사항**
  - 출발점은 불편함이다 — 매번 새 대화마다 **같은 기준을 다시 설명**하고, 사람마다 결과가 달라진다
  - 프로젝트 = **반복업무 전용 작업공간**. 기준(지침)과 참고자료를 **미리 넣어두는 방**
  - 일반 챗 = '처음 만나는 사람에게 매번 처음부터 설명' / 프로젝트 = '우리 팀 사정을 아는 담당자에게 맡기기'
  - 화면에서 위치를 먼저 찾게 한다 — 왼쪽 메뉴의 프로젝트
  - **만드는 절차를 실제 화면으로** 보여준다 — 프로젝트 화면 오른쪽 위 [+ 새 프로젝트] → 이름·설명 입력 → 저장
  - 이어서 **리소스(참고자료) 등록**까지 화면으로 보여준다 — 리소스 탭 > [＋ 리소스 추가하기] →
    업무보고서 양식 파일 선택 → 파일 1개 등록 + AI 요약 자동 생성
  - 지시사항을 설명하기 전에 **프롬프트 프레임**을 먼저 다룬다 (2026-09-06 추가)
    - 문제 — 막연히 “잘 써줘”라고 하면 결과가 들쭉날쭉하고 다시 요청하는 일이 반복된다
    - 이유 — **요청이 짧을수록 AI가 빠진 부분(분량·형식·톤·독자)을 스스로 추측**하고,
      그 추측이 매번 달라지기 때문이다. 문제는 AI 성능이 아니라 **요청에 빠진 칸**이다
    - 해결 — 기억하기 쉬운 **1개 프레임: CO-STAR** (싱가포르 프롬프트 대회 우승자가 쓴 틀)
      맥락(Context) / 목표(Objective) / 스타일(Style) / 톤(Tone) / 대상(Audience) / 응답형식(Response)
    - 효과 — 추측할 자리가 줄어 **같은 요청이면 비슷한 결과**가 나오고, 고칠 곳만 짚으면 끝난다.
      '검토기준'을 미리 주면 AI가 스스로 확인하고 내므로 재작업이 줄어든다
    - 연결 — CO-STAR 중 **맥락 · 스타일 · 톤 · 대상 · 응답형식은 매번 같다.**
      이 다섯 칸을 프로젝트 **지시사항**에 미리 붙여두면 다음부터는 **목표 한 줄**만 적으면 된다
      → H Chat Pro '프로젝트'의 지침 문서로 활용된다는 점을 여기서 잇는다
  - **지시사항**은 '리소스=자료 / 지시사항=규칙'으로 구분해 설명한다.
    적는 내용은 **CO-STAR를 그대로 쓴다** — 여기에 적는 칸은 **맥락 · 스타일 · 톤 · 대상 · 응답형식**,
    요청할 때 적는 칸은 **목표**. 교안에는 칸 이름이 붙은
    **빈칸만 채우면 되는 문장**을 [복사] 버튼으로 제공한다
  - 실제 예시(업무보고서 프로젝트)도 **CO-STAR 순서 그대로** 적어, 프레임이 그대로 지시사항이 된다는 것을 보여준다
  - 이어지는 실행 화면에서는 남은 것이 **'목표' 한 줄뿐**임을 짚는다 (“사내 축구대회 리그 일정협의 포상”)
  - 마지막으로 **지시사항(규칙)** 을 적어두고 **키워드만 넣어 결과를 받는 장면**까지 보여준다
    - 지시사항 예시 — “업무보고서 양식에 맞게 내가 키워드만 넣으면 초안을 만들어주는 프로젝트야.
      작성일은 내가 만드는 날짜로, 부서는 인사팀, 작성자는 김현복. 보고대상과 결재자는 부장님·팀장님·이사님 중에서
      선택할 수 있게 해줘. 나머지는 키워드에 맞게 생성해줘.”
    - 실행 예시 — 요청은 키워드 한 줄뿐: **“사내 축구대회 리그 일정협의 포상”**
    - 결과로 작성일·부서·작성자·보고대상·결재자가 규칙대로 채워지고, 개요·세부 내용·결과·향후 계획까지 양식대로 생성됨
    - 규칙을 세 종류로 정리해 준다 — **고정할 것**(부서·작성자) / **자동으로 채울 것**(작성일) / **고르게 할 것**(보고대상·결재자)
  - M1과 연결 — 모델(엔진)을 골랐다면, 이번엔 **일하는 방(작업공간)** 을 만든다
- **현업 적용**: 매주 같은 형식으로 만드는 보고서·회의록·메일마다 방을 하나씩 만들어 둔다

### M2-2. 나만의 반복업무 프로젝트 만들기 `09:30~09:55 · 25분` · 개념+실습

- **교안 반영 유의사항**
  - 순서는 **참고자료 → 지시사항**. 자료를 먼저 넣고, 그 자료를 어떻게 쓸지 규칙을 적는 흐름

    **지시사항 빈칸 문장 = 그중 매번 같은 다섯 칸을 방에 미리 붙여두는 것**.
    실습에서는 지시사항 빈칸 문장 하나만 쓰게 한다

  - 보고서 채우기 외 **다른 활용 예시**를 함께 제시 — 회의록 방(녹취 → 팀 양식 회의록) /
    메일 방(상황 → 사내 톤 초안) / 번역 방(팀 용어집대로 통일) / 정리 방(엑셀 서식대로 표)

- **[실습] 나만의 반복업무 프로젝트 만들기** *(기존 M1-4 실습을 이관)*

  - **실습 전 설명**: 매번 같은 기준을 새 대화마다 다시 입력 → 프로젝트에 '우리 팀 전용 작업공간'처럼 기준을 미리 넣으면 매번 같은 품질
  - **절차**
    1. 내가 매주 반복하는 업무 1개 선택 (보고서 / 회의록 / 번역 / 고객 응대 / 자료 정리 중)
    2. H-Chat **프로젝트 생성** (이름 · 설명 한 줄)
    3. **참고자료(리소스) 등록** — 우리 팀 양식 1~2개 (Word · Excel · PPT · PDF)
    4. **지시사항 입력** — 빈칸 문장에 내 규칙 채우기
    5. 프로젝트 채팅에서 실제 요청 1개 실행 → 결과 확인
    6. 일반 챗에 같은 요청 → 두 결과 비교 → '무엇이 달라졌는지' 3줄 메모
  - **준비물**: 지침 템플릿 1종(교육생 배포) / 사내 표준 회의록 양식(목업) / 동일 시나리오 입력 1종
  - **실패 대비**: 프로젝트 생성이 막히면 **지침을 대화 맨 앞에 붙여넣는 방식**으로 같은 효과를 확인
  - **현업 적용**: 매주 같은 형식의 보고서·이메일·회의록 작성 시 '다시 세팅'하는 시간 단축

### M2-5. Pro와 데스크탑은 무엇이 다른가 — Agent의 차이 `10:25~10:45 · 20분` · 개념

- **교안 반영 유의사항**
  - '둘 다 같은 AI인데 왜 두 개를 쓰나'라는 의문을 **먼저** 풀어준다
  - 핵심 메시지: **차이는 모델이 아니라 Agent다**
  - 도입은 **같은 요청 · 다른 결과**로 연다 — “오늘 뉴스 정리해서 pdf로 뽑아줘”를
    **같은 모델(Sonnet 5)** 로 H-Chat Pro와 데스크탑에 각각 넣은 결과를 나란히 보여주고 **“왜 다를까요?”** 를 묻는다
    (Pro : “PDF 파일 자체를 생성·첨부할 수는 없습니다” / 데스크탑 : 스킬을 써서 PDF 파일 생성)
  - Agent는 세 가지로 이루어진다 — **환경인식 → 판단 → 행동**
    - **환경인식** : 무엇을 볼 수 있는가 (대화창에 올린 파일 · 내 PC의 폴더)
    - **판단** : 본 것을 바탕으로 무엇을 할지 정한다 → **모델의 영역** (M1에서 고른 그 엔진)
    - **행동** : **가진 도구로** 무엇을 할 수 있는가 (글쓰기 · 그림 생성 · 파일 만들기)
  - 앞의 PDF 차이를 여기서 회수한다 — 파일을 만든 것은 모델이 아니라 **도구(스킬)** 다.
    데스크탑에는 그 도구가 있고 브라우저 Pro에는 없다. **같은 모델이라도 가진 도구가 다르면 할 수 있는 일이 달라진다**
  - **판단(모델)은 Pro와 데스크탑이 같을 수 있다.** 같은 모델을 고를 수 있기 때문
  - **환경인식과 행동은 Agent마다 다르다.** 그래서 같은 모델을 써도 **할 수 있는 일이 달라진다**
  - 이것이 H-Chat Pro와 H-Chat 데스크탑이 다른 이유다
  - 앞 세션과 연결 — 커넥터는 Pro의 **환경인식을 넓히는 장치**, 데스크탑은 **환경인식과 행동을 함께 넓힌 Agent**
  - 비유 — 같은 사람(판단)이라도 **전화로 방법만 알려주는 사람**과 **내 자리에 앉아 서랍을 직접 열어 정리해주는 사람**은 다르다
  - M1과 연결 — 모델 = '엔진', Agent = '그 엔진을 실은 차'. 엔진이 같아도 트럭과 승용차는 할 수 있는 일이 다르다
- **마무리는 전자레인지 · 오븐 비유로** — Pro = 전자레인지(버튼 하나로 바로 **데워** 내준다),
  데스크탑 = 오븐(온도·시간이 있어 처음엔 낯설지만 **구워서 만들어 낸다**).
  앞의 PDF 예시(내용은 주지만 파일은 못 만든다 / 파일을 만들어 낸다)와 그대로 맞물리고,
  뒤의 **스킬 = 레시피** 설명으로 이어진다.
  “버튼이 많아 어색한 것은 잠깐”이라는 메시지로 데스크탑 실습에 대한 부담을 낮춘다
  *(그림은 교안 색상으로 그린 삽화 — 별도 이미지 파일 없음)*
- **비교표 (강사 참고용 — 교안에는 그랜저 비유로 대체)**

  | | H-Chat Pro (브라우저) | H-Chat 데스크탑 (내 PC) |
  |---|---|---|
  | 환경인식 — 무엇을 보는가 | 대화창에 올린 파일 · **커넥터로 연결한 사내 자료** | **내 PC의 폴더와 파일** |
  | 판단 — 누가 정하는가 | 내가 고른 모델 | 내가 고른 모델 *(같다)* |
  | 행동 — 무엇을 할 수 있는가 | 답변 작성 · 화면 미리보기 · 대화 안의 결과물 | **파일 만들기 · 고치기 · 폴더 정리** |
  | 어울리는 일 | 묻고 답하기 · 초안 작성 · 사내 자료 요약 | 내 PC에 흩어진 자료 정리 · 문서 만들어 저장 |

- **정리 문장**: "모델을 바꾸면 **판단**이 바뀌고, Agent를 바꾸면 **보는 것과 할 수 있는 일**이 바뀝니다."
- **[개념] Effort — 얼마나 깊이 생각할지** (그랜저 비유 뒤에 짧게)
  - 모델이 '누가 일할지'라면 Effort는 '얼마나 공들일지' — 같은 사람에게 "쓱 훑어봐" / "꼼꼼히 들여다봐"의 차이
  - 위치는 **모델 이름 옆 Effort > 낮음 · 중간 · 높음**
  - 낮음 = 빠르게 훑고 답한다(단순 정리·형식 맞추기) / 중간 = 기본값 / 높음 = 오래 꼼꼼히(복잡한 판단·긴 문서)
  - "급하면 낮음, 중요하면 높음. 헷갈리면 그대로 두어도 된다"로 마무리 — 선택 부담을 주지 않는다
  - **준비물**: 데스크탑 Effort 화면 캡처
- **현업 적용**: 업무를 만났을 때 '이건 물어보면 되는 일인가, 내 PC의 파일을 만져야 하는 일인가'로 도구를 고른다
